# 04 — Pantallas

Mobile-first. Todo se diseña primero para **375 px de ancho** y luego se expande. El vendedor
trabaja de pie, con una mano, en un mostrador.

Convenciones de este documento: `[campo]` input, `(botón)`, `«texto»` copy literal a usar tal cual.

---

## 0. Shell de la aplicación

### Navegación

**Móvil (< 768 px)** — barra inferior fija, máximo 4 destinos + menú.

```
┌─────────────────────────────────────┐
│  Convenios            🌓   👤       │  ← header 56px, sticky
├─────────────────────────────────────┤
│                                     │
│           contenido                 │
│                                     │
├─────────────────────────────────────┤
│  🏠      ➕       📋       ☰        │  ← tab bar 64px, safe-area-inset-bottom
│ Inicio  Nueva   Ventas   Más        │
└─────────────────────────────────────┘
```

**Escritorio (≥ 768 px)** — sidebar fijo de 260 px, sin tab bar.

### Destinos por rol

| | VENDEDOR | ADMIN_EMPRESA | SUPERADMIN |
|---|---|---|---|
| Tab 1 | Inicio | Dashboard | Dashboard |
| Tab 2 | **Nueva venta** (destacado) | **Nueva venta** | Empresas |
| Tab 3 | Mis ventas | Ventas | Convenios |
| Tab 4 «Más» | Perfil, Cerrar sesión | Empleados ·badge·, Usuarios, Sedes, Auditoría, Perfil | Usuarios, Auditoría, Perfil |

El badge de «Empleados» muestra el conteo de pendientes de verificación. Si es 0, no se muestra.

### Header
Izquierda: nombre de la app y, debajo en texto pequeño, el nombre comercial de la empresa del
usuario. Derecha: toggle de tema y menú de usuario (nombre, rol, «Cerrar sesión»).

### Estado offline
Banner fijo bajo el header, ámbar:
«Sin conexión. Puedes seguir llenando el formulario, pero no podrás guardar hasta recuperar
la señal.»
Los botones de guardado quedan deshabilitados con tooltip explicativo.

### Comportamiento paso a paso

**Empresa convenio**
- Se llena con `misConveniosVigentes`.
- 0 convenios → se reemplaza todo el formulario por el estado vacío:
  «Tu empresa no tiene convenios vigentes. Contacta al administrador general.»
- 1 convenio → texto fijo, no select. El foco arranca en el DNI.
- Cambiar la empresa limpia el empleado seleccionado.

**DNI**
- Solo dígitos. Al llegar a 8 caracteres, **busca automáticamente** (sin pulsar el botón).
- Durante la búsqueda: spinner en el botón, campo de nombre en skeleton.
- Debounce 300 ms; cancelar la petición anterior si el usuario sigue escribiendo.

**Resultados de la búsqueda** (`buscarPorDni`, ver [`03 §6`](./03-API.md)):

| Resultado | UI |
|---|---|
| `encontrado` | Llena nombre, muestra chip de descuento, avanza foco al monto. Si `estado = PENDIENTE_VERIFICACION`, chip ámbar «Pendiente de verificación» y texto «Puedes registrar la venta; el administrador de FastFood SA confirmará los datos». |
| `NO_EXISTE` | Panel con «No encontramos este DNI» + botón `( + Crear empleado )` que abre la hoja modal (§5). |
| `PROPIA_EMPRESA` | Alerta roja con el copy de [`02 §4`](./02-LOGICA-NEGOCIO.md). No permite continuar. |
| `SIN_CONVENIO` | Alerta roja nombrando la empresa. No permite continuar. |
| `NO_HABILITADO` | Alerta roja «Este empleado no está habilitado para el beneficio. Contacta al administrador de su empresa.» |

**Monto y total**
- El total se recalcula en cliente con el `descuentoBps` recibido.
- Si el usuario cambia la **fecha** a un día pasado, se llama a `previsualizarDescuento` porque
  el término vigente pudo ser distinto. Si el bps cambia, se muestra un aviso discreto:
  «En esa fecha el descuento era 12%.»
- Al superar el tope de la empresa: borde rojo + «El monto no puede superar S/ 50,000.»

**Adjuntos**
- Botón «Tomar foto»: `<input type="file" accept="image/*" capture="environment">`.
- Botón «Elegir archivo»: `<input type="file" accept="image/*,application/pdf">`.
- La compresión ocurre inmediatamente tras seleccionar; mientras tanto la miniatura muestra
  un spinner y el botón de guardar se deshabilita.
- Subida en segundo plano a Blob apenas se comprime, con barra de progreso en la miniatura.
- Si la empresa tiene `requiereEvidenciaEnVenta`, la sección Evidencia se marca con `*` y su
  ausencia bloquea el guardado.

**Guardar**
- Deshabilitado hasta que: empleado resuelto + sede + fecha válida + monto > 0 + documento
  subido (+ evidencia si aplica).
- Al pulsar: el botón entra en estado de carga y **se bloquea contra doble pulsación**.
- Éxito → pantalla de confirmación (§4b). El borrador local se borra.
- Error de red → el borrador se conserva y se muestra «No pudimos guardar. Revisa tu conexión e
  intenta de nuevo.» con botón `( Reintentar )` que reenvía **el mismo `ventaId`**.

### Borrador local (D08)
- Se persiste en `localStorage` bajo la clave `venta-borrador:<usuarioId>` en cada cambio,
  con debounce de 500 ms.
- Contiene: `ventaId`, empresa, empleado resuelto, sede, fecha, monto, observación y las rutas
  de blob ya subidas. **No** contiene los archivos en sí.
- Al abrir el formulario con un borrador existente de menos de 24 h: banner
  «Tienes una venta sin terminar. ( Continuar ) ( Descartar )».
- Se borra al guardar con éxito o al descartar.

### 4b. Confirmación

```
        ✓
   Venta registrada

   María Quispe Rojas
   FastFood SA · Principal
   03/08/2026

   Monto        S/ 120.00
   Descuento    − S/ 18.00  (15%)
   ─────────────────────────
   Total        S/ 102.00

   ( Registrar otra venta )     ← primario
   ( Ver detalle )

```
«Registrar otra venta» conserva empresa y sede, limpia todo lo demás y deja el foco en el DNI.

## 12. `/auditoria`

Timeline invertida, agrupada por día.

```
── 03 de agosto de 2026 ─────────────────

 14:32  🧾  Juan Pérez registró una venta
            Venta a María Quispe · S/ 120.00
            [ Ver detalle ]

 14:30  🔍  Juan Pérez buscó el DNI 45678912
            Resultado: encontrado

 09:15  👤  Ana Torres verificó al empleado
            Carlos Mendoza (50000008)
            [ Ver cambios ▾ ]
              nombres:  "carlos" → "Carlos"
              estado:   PENDIENTE_VERIFICACION → ACTIVO
```

- Filtros: rango de fechas, tipo de acción, actor, entidad.
- «Ver cambios» despliega el diff campo a campo entre `datos_antes` y `datos_despues`, no el
  JSON crudo. Los campos sin cambio no se muestran.
- Ícono y color por familia de acción: sesión, venta, empleado, usuario, configuración, acceso.
- SUPERADMIN ve además un botón `( Verificar integridad )` que corre `verificarCadena` y muestra
  «Cadena íntegra: N registros verificados» o el `id` donde se rompió.

## 13. `/admin/empresas` y `/admin/convenios` — SUPERADMIN

**Empresas**: tarjetas con nombre comercial, RUC, contadores (usuarios, empleados, convenios) y

## 14. Estados transversales

| Estado | Tratamiento |
|---|---|
| **Carga** | Skeletons con la forma del contenido real. Nunca un spinner a pantalla completa salvo en la verificación inicial de sesión. |
| **Vacío** | Ícono, frase que explique *por qué* está vacío, y la acción siguiente si existe. |
| **Error de red** | Tarjeta con «No pudimos cargar esta información» + `( Reintentar )`. Nunca una pantalla en blanco. |
| **403** | «No tienes permiso para ver esta página» + enlace al inicio. Sin detalles del recurso. |
| **404** | «No encontramos lo que buscas» + enlace al inicio. |
| **500** | Mensaje genérico + el `requestId` visible, con botón de copiar, para soporte. |
| **Sesión expirada** | Redirección a `/login` con `?volver=<ruta>` y aviso «Tu sesión expiró». |

## 15. Accesibilidad — requisitos mínimos

- Objetivos táctiles de **44×44 px** como mínimo.
- Todo input con `<label>` asociado; nunca solo `placeholder`.
- Contraste AA (4.5:1 en texto normal) verificado en tema claro **y** oscuro.
- Foco visible en todos los elementos interactivos, sin `outline: none` sin reemplazo.
- Errores de formulario anunciados con `aria-live="polite"` y `aria-invalid` en el campo.
- El formulario de venta debe ser completable solo con teclado.
- Ningún estado se comunica únicamente por color: siempre acompañado de texto o ícono.

**Service worker (Serwist)**
- Precache del shell, CSS, JS e iconos.
- `NetworkOnly` para todo `/api/*` y todas las Server Actions. **Nunca** cachear datos de negocio.
- `CacheFirst` para fuentes e iconos.
- Página offline dedicada para navegaciones sin red.

**Prompt de instalación**: capturar `beforeinstallprompt` y mostrar un banner discreto tras la
segunda visita, descartable y con memoria de que fue descartado. No interrumpir el formulario de
venta.
